# ADR 0010: Fail-closed relaxations, formatter removal and the kimchi helper allowlist

- **Status:** Accepted
- **Date:** 2026-11-20
- **Deciders:** review-gate maintainers, following the review-speed work
  (branch `fix/review-speed`).
- **Implementation:** `scripts/review-gate.py` (inline wait, supervisor
  restart and failure reasons, docs-summary background regeneration, canary
  cache, spotter skip, kimchi `helper_cmds`), `scripts/ocr_render.py`,
  `scripts/rg_settings.py`, `extensions/review-gate-deny.ts`,
  `skills/review/SKILL.md`.
- **Related:** ADR 0001 (verdict authority, item 6 amended here), ADR 0005
  (backend profiles and the helper allowlist, kimchi note added here).

## Context

Pushes were failing or stalling for reasons that had nothing to do with the
code under review. The measured causes (see the review-speed reconciliation)
were: a 4 s inline wait clamp that denied the first push of almost every
review with "still running, re-run"; a docs-summary generation session that ran
serially before the review and blocked the push when it failed; a deep-lane
timeout that was not retriable; a dead supervisor that respawned with its
attempt counter reset and no reason shown, so three pushes exhausted a tip
without the operator ever seeing the real error; an extra LLM "formatter"
session after every review; and a kimchi sandbox that blocked the
`python3` helper steps the skill depends on.

Several of these are fail-closed behaviors. This ADR records each relaxation
and states why the gate still never allows a push on a timeout or a failure.

## Decision

### 1. Docs-summary failure no longer blocks a push on its own

- **Old:** a stale or missing `.ocr/docs-summary.md` was regenerated by a model
  session before the review started. A generation failure or timeout blocked
  the push.
- **New:** regeneration runs on a background thread. The manifest build waits
  at most `OCR_DOCS_SUMMARY_WAIT` seconds (default 5, measured from the start of
  the regeneration). Past that, or if generation fails, the docs context falls
  back to a diff-based context (`summary_unavailable: true` in the manifest,
  with pointers into the docs corpus) and the review proceeds. The gate adds a
  visible `docs summary unavailable` warning to the reasons, the deny text and
  the record. A summary that finishes late (up to a 15 s join after the review)
  still lands for the next push; otherwise the generator child is killed.
- **Why it stays safe:** the docs-checker still runs on the diff-based context
  and its findings still merge into the verdict and can still block. Only the
  summary as an *input convenience* became best effort; the unavailability is
  reported, never silent. A push is still blocked by any blocking finding.

### 2. A deep-lane timeout gets one retry

- **Old:** a deep review that hit its wall-clock cap failed non-retriably.
- **New:** the first deep-lane timeout is recorded as the retriable reason
  `review-timeout` (counts one attempt, sets `timeout_retries=1`); the next
  push retries it. A second deep timeout fails with the real
  `review timed out after Ns` detail and is sticky like other non-retriable
  failures. Fast-lane timeouts are unchanged.
- **Why it stays safe:** the push that timed out is denied, not allowed; the
  retry is a fresh full review whose result is the only way the tip passes.
  The attempt cap still applies and the exhausted state still needs
  `--reset-tip`.

### 3. A longer inline wait on the claude and git paths

- **Old:** every path clamped the inline wait to 4 s (`_INLINE_BUDGET_MAX`),
  a limit inherited from the kimchi hook.
- **New:** the claude hook waits `behavior.inline_wait_seconds.hook` seconds
  (default 300, hard cap 840, below the 900 s `hooks.json` timeout; env
  `OCR_INLINE_BUDGET` wins). Git mode (pre-push) waits
  `behavior.inline_wait_seconds.git` (default 300; env `OCR_INLINE_BUDGET_GIT`
  wins) when stderr is not a terminal, i.e. inside an agent's Bash tool whose
  ceiling is 600 s, and the full reviewer timeout when it is a terminal. The
  **kimchi hook keeps its short wait** (3 s default, never above 4 s) because
  kimchi kills a bash hook at 5 s. An unknown harness is treated as kimchi.
- **Why it stays safe:** the wait only decides how long the hook polls for the
  verdict. On expiry the hook still **denies** with "still running" and a
  re-push joins the same run; it never allows because time ran out.

### 4. A dead supervisor counts as an attempt and the deny shows the real error

- **Old:** a stale running/claimed state respawned with `attempts=0` and no
  reason; a rate-limit pattern matched any mention of "rate limit" in a long
  transcript; the deny hid the worker's own error.
- **New:** a dead supervisor carries `attempts+1` into the restart; at the
  attempt cap the state is written `exhausted` with reason `crash` and the
  detail "the review supervisor died or never started"; `--force` still
  resets. The deny text includes the worker error plus the first lines of the
  supervisor log (sanitized, bounded to 900 characters). The usage-limit
  classifier needs a real rate-limit error shape and scans stderr plus only
  short or final-line stdout.
- **Why it stays safe:** this makes failure *stricter and more visible*, not
  looser. Nothing here can turn a failed or missing review into an allow.

### 5. The formatter session is removed; Python renders

- **Old:** after the reviewer, the skill spawned a model "formatter" subagent to
  turn raw findings into the status/summary/verdict message (ADR 0001 item 6
  required it for chunk sessions), and the skill's §3a re-read cited files in
  the model to drop findings whose quoted evidence was missing.
- **New:** the gate renders status, summary and verdict itself from the raw
  results (`scripts/ocr_render.py`). The enumerated parse classes (bare arrays,
  wrapper keys such as a `findings` object, trailing commas) are handled in
  Python; anything else still fails closed after the retry. The §3a quote
  check moved to Python: a finding whose quoted evidence is not found in the
  cited file gets a **confidence downgrade of 0.3** and a visible warning. It
  is a downgrade, **not a drop**: the finding stays in the verdict computation
  (a `high` finding at 0.95 becomes 0.65 and still blocks). Documentation
  findings are skipped by the check; contract-object answers are untouched.
- **Why verdict authority is preserved:** `ocr_verdict.compute_verdict`
  remains the **sole** verdict authority exactly as ADR 0001 requires. Python
  rendering reads the same raw results the formatter did and recomputes the
  verdict from the findings; a model-supplied `verdict` key is still never
  trusted. Removing a model session removes a place where a verdict could be
  mis-relayed. The prompt-side formatter mandate of ADR 0001 item 6 is
  withdrawn; the gate-side rescue families and their telemetry stay.

### 6. Kimchi exact-script helper allowlist

- **Old:** the kimchi deny extension blocked every `python`/`python3` use and
  the kimchi profile published no `helper_cmds`, so the conventions, demands
  and collectors steps of the skill failed (ADR 0005 item c gave the helper
  allowlist to the claude profile only).
- **New:** the extension admits exactly the interpreter word plus the exact
  plugin-root paths of `scripts/ocr_conventions.py`, `scripts/ocr_demands.py`
  and `scripts/ocr_collectors.py` with a fixed per-script argument grammar. A
  quoted heredoc is accepted only as stdin of those commands. The commands are
  published as `manifest.helper_cmds` and the skill uses them verbatim.
  `python -c`, any other script (including `review-gate.py`), a prefix or `..`
  path trick, extra or `=`-form arguments, command chaining (`;` `&&` `|`
  `$()`) and an unquoted heredoc all stay denied.
- **Why the sandbox is not weakened:** the allowlist is exact-match on three
  read-only helper scripts the reviewer's own skill ships; there is no general
  interpreter access. The canary still proves the deny extension loaded before
  any review (see Related behavior below).

## Related behavior shipped with this work

- **Canary cache.** A passed kimchi deny-extension canary is remembered for
  `behavior.canary_cache.ttl_days` (default 7) keyed on the kimchi version, the
  hash of the deny extension and the canary model. A failed, corrupt, expired
  or future-dated entry is a miss and a failed probe is never stored, so a
  changed extension or CLI always re-probes.
- **Spotter skip: shipped default off.** `behavior.spotter_skip` can skip the
  spotter for a docs-only push or a tiny change (default limits 3 files and 60
  changed lines), but `enabled` defaults to `false` until the cross-file recall
  scenarios (Part S) are run against a real kimchi. Risk-glob escalation to the
  deep lane is unaffected by the skip. **Known limitation:** the review
  fingerprint does not include the spotter-skip state, so a cached record from a
  skipped push can carry over to a push that would not have skipped. This is
  acceptable while the feature is off and must be closed before the default
  changes.
- **Parallel docs-checker.** `behavior.docs_checker_parallel` (default true)
  spawns the docs-checker beside the reviewer; its findings merge identically.

## Consequences

- **Fail-closed is intact.** Every relaxation above either shortens work that
  was never a safety property (a serial summary session, a 4 s wait, a
  formatter relay) or makes the failure report more honest. In no case does a
  timeout, a missing summary, a dead supervisor or an unparseable result
  allow a push: timeouts deny with "still running", failures stay failures,
  and the attempt cap and `--reset-tip` still govern exhaustion.
- **Verdict authority is unchanged.** `compute_verdict` is the only decision
  maker; the quote check only adjusts a finding's confidence input to it.
- **Reviewers see a smaller toolbox change under kimchi** (three exact helper
  scripts), documented here and in ADR 0005.
- **Residual risks:** the spotter-skip fingerprint gap above; a docs-checker
  that runs on diff-based context sees less than one that reads the summary
  (the warning says so); real-kimchi behavior of the new model pins and
  `:high`/`:max` thinking suffixes is verified by `scripts/kimchi-verify.sh`,
  not by the test suite.
- Future changes to these timeouts, retry counts, the render path or the
  helper allowlist require updating this ADR or a successor.
